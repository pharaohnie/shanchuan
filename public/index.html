    🐊 Croc WASM 工作原理

      浏览器发送方 ══WebRTC P2P══ 浏览器接收方  （优先，Cloudflare STUN 打洞）
        │                                              │
        │  失败时回退：WebSocket ──→ [中继] ←── WebSocket
        │  PAKE 密钥交换 + AES-GCM 端到端加密（密文不经服务器解密）
    1
    PAKE 密钥交换

    发送方和接收方使用相同的口令码，通过 SPAKE2 协议在浏览器中协商出共享密钥。
    中继服务器无法得知密钥内容

    2
    WebRTC P2P 直连

    密钥建立后，双方通过 Cloudflare STUN 尝试浏览器间直连（WebRTC DataChannel）。成功时文件密文不经中继服务器。
    NAT 复杂时自动回退 WebSocket 中继转发

    3
    端到端加密

    文件在发送方浏览器中用 AES-256-GCM 加密，接收方浏览器解密。
    中继服务器只能看到密文，无法解密文件内容

    4
    Go WASM 核心

    PAKE 和加密逻辑由 Go 编译为 WebAssembly 在浏览器中运行，性能接近原生。
    基于 croc 的 schollz/pake 和 golang.org/x/crypto

    技术栈

    Go WASM SPAKE2 PAKE AES-256-GCM WebRTC P2P WebSocket
